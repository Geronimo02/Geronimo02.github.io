01 / Qué cambió el 7 de octubre

De configurar a mano a descubrir desde /model.

Desde GitHub Copilot CLI 1.0.94-0, al ejecutar /model podés ver modelos compatibles en una instancia local de Ollama que ya esté funcionando, junto a los modelos configurados y de GitHub. Elegís un modelo, revisás proveedor y endpoint y confirmás “Add and use for this session” o “Add without switching”. No hace falta reiniciar la CLI para usarlo en esa sesión.

ANTES

Menos directo

GitHub había incorporado conexión con proveedores externos y modelos locales el 7 de abril. El funcionamiento local ya existía; configurar proveedor y variables era la fricción principal.

AHORA

Descubrimiento dentro del flujo

La CLI detecta los modelos compatibles del Ollama activo. No descarga modelos automáticamente y tampoco transforma tu sesión en offline por sí sola.

PRECIO / DISPONIBILIDAD: Ollama es gratuito y open source; ejecutar modelos locales no implica pagar tokens de una API en la nube, aunque consume recursos de tu máquina y energía. Copilot CLI permite conectar un proveedor propio/local y, según el anuncio oficial del 7/4, usar proveedor propio sin autenticación GitHub. Los modelos alojados por GitHub, funciones de búsqueda/delegación y solicitudes premium dependen de la autenticación, cuotas o plan de Copilot. No confundas “software instalable” con “todas las funciones gratis”.
Seguridad: elegir Ollama no activa COPILOT_OFFLINE=true ni desactiva automáticamente la telemetría. Además, si configurás un proveedor remoto, ese proveedor puede recibir código y prompts incluso con modo offline. El endpoint realmente importa.
02 / Cuándo tiene sentido

Mi criterio: primero elegí el trabajo.

Revisar un script en privado

Querés entender qué hace un script interno, detectar riesgos obvios o preparar una corrección. Un modelo local puede ayudar sin mandar el archivo a un modelo hospedado. La revisión final sigue siendo tuya.

Prototipar funciones chicas

Generar tests de una función, documentar un endpoint o proponer refactors acotados. Para arquitectura compleja, evaluá si el modelo local realmente alcanza.

Equipos con conectividad limitada

Si tenés que trabajar sin internet, combiná COPILOT_OFFLINE=true, un proveedor local y las dependencias instaladas previamente.

Aprender sobre agentes

Un proyecto de prueba donde puedas observar qué archivos quiere leer, qué comandos propone y cómo pide aprobaciones, sin tocar producción.

No lo vendería como magia: ejecutar un modelo local no hace que sea automáticamente tan bueno como uno grande en la nube. La calidad depende del modelo, soporte de herramientas, contexto real, hardware, prompt y tarea.
03 / Tutorial controlado

De cero a una primera sesión.

Este es el orden que seguiría para no confundir un problema de instalación, un modelo incompatible o una configuración remota con un error del agente.

01

Instalá Ollama desde la fuente oficial

Descargalo desde ollama.com y comprobá que el runtime esté disponible. Si el servicio no está corriendo, iniciá Ollama siguiendo la documentación de tu sistema.

ollama --version
ollama list
02

Elegí un modelo compatible con herramientas

Desde la biblioteca oficial, buscá un modelo que soporte tool calling y streaming. Descargalo según el identificador exacto de la ficha del modelo.

ollama pull NOMBRE:VARIANTE
ollama list

“NOMBRE:VARIANTE” es un marcador, no un modelo real. Comprobá RAM/VRAM y longitud de contexto; GitHub recomienda 128k tokens para mejores resultados, pero no todos los modelos o equipos pueden usarlo.

03

Instalá GitHub Copilot CLI

Elegí el método oficial que corresponda. En equipos con Node/npm disponible, el repositorio documenta:

npm install -g @github/copilot
copilot

Alternativas oficiales: winget install GitHub.Copilot en Windows y brew install copilot-cli en macOS/Linux. Consultá requisitos y versión mínima en el repositorio.

04

Abrí el selector de modelos

Con Ollama funcionando, desde Copilot CLI escribí:

/model

Revisá los modelos locales encontrados. Verificá proveedor y endpoint, elegí el modelo compatible y confirmá Add and use for this session.

05

Si no aparece, revisá antes de insistir

Comprobá la versión de Copilot CLI, que Ollama esté en ejecución, que haya modelos instalados y que sean compatibles con herramientas y streaming. Mirá la explicación que el selector muestra para errores de conexión.

copilot help providers
06

Hacé una prueba de solo lectura

Usá una carpeta de ejemplo, idealmente un repositorio descartable, y pedile que explique código sin editarlo. Observá qué quiere ejecutar y no apruebes comandos ni cambios que no entiendas.

Ollama→Modelo instalado→Copilot CLI→/model→Revisión
04 / Lo que casi nadie explica

Local no siempre significa offline.

Hay tres cosas distintas: dónde corre el modelo, a qué servidores puede hablar la CLI y qué herramientas externas autorizás al agente. Si querés una sesión realmente aislada, hay que revisar las tres.

macOS / Linux

Con el proveedor local ya preparado, podés lanzar una sesión con el modo offline explícito:

COPILOT_OFFLINE=true copilot

Windows · PowerShell

Para esa terminal, configurá la variable antes de iniciar:

$env:COPILOT_OFFLINE = "true"
copilot
Chequeo obligatorio: el modo offline impide contactar servidores de GitHub desde la CLI, pero no evita que un proveedor remoto configurado reciba información. Confirmá que el endpoint sea local (por ejemplo, 127.0.0.1), cerrá integraciones externas y comprobá el tráfico si el caso necesita garantía técnica.

Para un entorno aislado, descargá antes CLI, modelo y dependencias. Funciones que requieren servicios de GitHub, como delegación o búsqueda remota, no forman parte de un flujo air-gapped.

05 / Prompts copiables

Probalo con un problema que puedas verificar.

1. Revisión de solo lectura

Quiero revisar este proyecto de práctica con un modelo local.
MODO: solo lectura. No ejecutes instalaciones, no escribas archivos y no uses red.
Objetivo: explicarme la estructura, detectar hasta 5 riesgos comprobables y proponer pruebas.
Separá HECHO OBSERVADO, HIPÓTESIS y VERIFICACIÓN NECESARIA.
Antes de cualquier herramienta que cambie algo, pedí mi aprobación.
No inventes archivos, funciones ni resultados de comandos.

2. Refactor pequeño, con autorización

Analizá esta función de ejemplo y proponé un refactor pequeño.
Primero: explicá el problema, impacto y prueba que demostraría la mejora.
Segundo: mostrame el diff propuesto SIN aplicarlo.
Tercero: enumerá comandos que necesitarías ejecutar.
Esperá mi confirmación explícita antes de escribir o ejecutar.
No cambies contratos públicos ni agregues dependencias sin justificarlo.

3. Comparar modelo local vs nube

Vamos a comparar asistentes sobre la misma tarea.
Criterios: exactitud verificable, tiempo de respuesta, pasos manuales, riesgos, privacidad y costo directo.
Entregá una tabla con el resultado y la evidencia de cada criterio.
Si no medimos algo, escribí NO MEDIDO.
No asumas que 'local' significa mejor, gratis en infraestructura o libre de errores.

Fallos comunes

  • Ollama no está abierto o no tiene modelos.
  • La CLI es anterior a 1.0.94-0.
  • El modelo no soporta herramientas o streaming.
  • El equipo se queda sin memoria.
  • Se asume que el modo local bloquea todas las conexiones.

Cómo lo evaluaría

  • Elegir tres tareas reales, pero con datos ficticios.
  • Repetir con el mismo input y permisos.
  • Contar propuestas correctas y errores graves.
  • Mirar consumo de RAM/VRAM y latencia.
  • Comparar tiempo total incluyendo correcciones.
Mi criterio: no quiero un agente local para poder decir que uso IA local. Quiero un flujo que me deje trabajar sin depender de un proveedor cuando sea importante y que pueda verificar. Si para una tarea simple el modelo necesita diez correcciones, cambio la tarea o cambio el modelo.

Checklist antes de un proyecto serio

  • Instalación y versión de ambas herramientas confirmadas.
  • Modelo, licencia, compatibilidad y hardware revisados.
  • Proveedor y endpoint verificados.
  • Modo offline explícito cuando sea necesario.
  • Permisos, comandos y cambios supervisados.
  • Datos y secretos protegidos.
  • Pruebas y comparación con alternativa documentadas.

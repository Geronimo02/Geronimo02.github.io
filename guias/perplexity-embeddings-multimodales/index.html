01 / Lo nuevo · 6–7 de octubre de 2026

No es otro chatbot. Es una forma distinta de buscar.

Perplexity publicó la familia pplx-embed-v2-late de modelos de recuperación multimodal. La investigación aparece fechada el 7 de octubre en Perplexity Research; la referencia bibliográfica del artículo registra el 6 de octubre. Los modelos pueden representar texto e imágenes, y puntuar consultas contra representaciones de páginas o pasajes.

01

Representación multivector

En vez de condensar una página entera en un único vector, conserva varios vectores asociados a tokens. Esa granularidad permite comparar diferentes partes de una consulta con partes distintas del documento mediante MaxSim.

02

Texto contra páginas visuales

Podés indexar una página renderizada como imagen y buscarla con una consulta de texto. Es útil para tablas, diagramas, ilustraciones y PDFs con estructura visual.

PRECIO / DISPONIBILIDAD: OPEN WEIGHTS / LICENCIA MIT en Hugging Face, con variantes 0.6B y 9B. Descarga gratuita del modelo; NO es un chatbot hospedado gratis. Necesitás ejecutar inferencia y sostener tu propio índice, CPU/GPU, almacenamiento y mantenimiento. El checkpoint del 0.6B ronda los 2,38 GB antes de considerar memoria en ejecución; 9B demanda recursos considerablemente mayores. La disponibilidad de la futura API de Perplexity es una cuestión distinta y no debe asumirse gratuita.

Mi lectura: la oportunidad no es “hablar con documentos” —eso ya existe— sino encontrar páginas pertinentes de documentación difícil cuando el texto extraído no cuenta toda la historia.

02 / Arquitectura comprensible

Cómo llega de un PDF a un resultado útil.

PDF→Página como imagen→Embeddings multivector→Índice→Consulta + MaxSim
01

Prepará el documento

Renderizá cada página como imagen y guardá metadatos: ID del documento, número de página, versión, origen y permisos de acceso. No pierdas ese vínculo; sin él, después no podés citar nada.

02

Generá representaciones del contenido

Con el modelo de Perplexity codificás páginas renderizadas, texto o ambos en lotes separados. La tarjeta oficial aclara que no admite mezclar entradas de texto e imagen en el mismo batch.

03

Guardá vectores + metadatos

Diseñá una persistencia que soporte múltiples vectores por página y pueda puntuar con MaxSim. No supongas que cualquier base vectorial con un campo embedding único implementa este método.

04

Codificá la pregunta del usuario

Una consulta como “¿dónde está la tabla de capacidad del equipo?” se transforma en su propia representación; el sistema busca las páginas relevantes.

05

Devolvé páginas, no certezas inventadas

El recuperador devuelve un ranking. Mostrá documento, página y vista previa. Si después sumás un modelo generativo para responder, ese segundo paso requiere controles y citas.

Importante: “sin OCR” significa que podés buscar en representaciones visuales de páginas sin extraer antes todo su texto. No significa que el sistema sea un lector perfecto, un motor de OCR validado ni una solución completa de preguntas y respuestas.
03 / Dónde yo lo probaría

Cuatro problemas de negocio.

Distribuidor con catálogos

Hay cientos de fichas PDF con tablas, fotos y especificaciones. El equipo pregunta por una característica; el sistema busca qué página del catálogo la contiene. El precio, stock y vigencia se verifican en las fuentes operativas reales.

Constructora y documentación de obra

Manuales, esquemas y fichas técnicas desparramadas en distintas carpetas. Buscás el diagrama o detalle correcto, con referencia al archivo y versión correspondiente. Un profesional sigue validando decisiones de seguridad.

Manuales de equipamiento

Cuando una instrucción aparece dentro de una figura o tabla, la búsqueda textual tradicional a veces la pierde. El buscador visual puede devolver la página para inspección manual.

Biblioteca de creatividades

Encontrar capturas, gráficos, layouts y documentos visuales a partir de una descripción escrita. No hace falta afirmar que comprende perfectamente cada imagen para que el filtrado sea útil.

Yo arrancaría por el catálogo. Tiene casos concretos que podés verificar rápido (“encuentra la página con la tabla X”) y no exige prometer que la IA va a tomar decisiones de negocio sin control.
04 / Primer experimento reproducible

Probarlo sin armar una startup.

En lugar de cargar 50.000 PDFs y medir “sensación de inteligencia”, prepararía un set chiquito con respuestas correctas conocidas. Así sabés si recupera lo que necesitás.

01

Elegí 3 PDFs públicos o propios

Que tengan diagramas, tablas o ilustraciones. No uses documentos privados sin autorización. Anotá 10–20 preguntas y la página exacta que debería aparecer.

02

Renderizá unas 20–30 páginas a PNG

Podés usar una librería de PDF como PyMuPDF u otra herramienta local. Mantené una convención documento_01_pagina_003.png y un registro de origen.

03

Instalá las dependencias confirmadas

La tarjeta oficial especifica sentence-transformers >= 6.0.0 y transformers >= 5.4.0. Probá en un entorno Python aislado y con hardware acorde.

python -m pip install 'sentence-transformers>=6.0.0' 'transformers>=5.4.0' pillow
04

Codificá pregunta y página

Ejecutá el ejemplo oficial adaptado de abajo. En la tarjeta usan MultiVectorEncoder y device="cuda"; esa configuración requiere una GPU CUDA. Para otro hardware, revisá compatibilidad y documentación antes de cambiar dispositivos a ciegas.

05

Compará con una búsqueda sencilla

Probá el mismo set con texto extraído + un buscador básico. Si el nuevo modelo no mejora recuperación de páginas visuales, no lo uses solo porque es nuevo.

06

Medí y decidí

Registrá Recall@5 (¿la página correcta aparece entre las cinco primeras?), tiempo por consulta, memoria, tiempo de indexación y errores por tipo de documento.

05 / Código y prompts

Un punto de partida técnico.

Este fragmento sigue el patrón documentado por Perplexity para puntuar una pregunta contra una imagen. Requiere que ya tengas una página PNG de prueba y las dependencias instaladas. No construye por sí solo un buscador en producción.

Prueba mínima sobre una página

from PIL import Image
from sentence_transformers import MultiVectorEncoder

model = MultiVectorEncoder(
    "perplexity-ai/pplx-embed-v2-late-0.6b",
    device="cuda",  # Requiere GPU CUDA compatible
)

preguntas = model.encode_query([
    "¿Dónde aparece la tabla de especificaciones?"
])

pagina = Image.open("documento_01_pagina_003.png").convert("RGB")
paginas = model.encode_document([pagina])
scores = model.similarity(preguntas, paginas)
print(scores)
Detalle de implementación: el modelo crea varios vectores por entrada y usa MaxSim. No lo reemplaces por una distancia coseno sobre un vector promedio sin justificarlo. La tarjeta oficial también indica que se deben separar lotes de texto y de imagen.

Prompt: diseñar el buscador

Quiero diseñar un buscador de PDFs con recuperación multimodal local.
Caso: [TIPO DE DOCUMENTOS]. Cantidad: [N]. Usuarios: [PERFILES].
Proponé un pipeline de render, embeddings multivector, índice MaxSim, filtrado de permisos y resultados con documento/página/cita.
Compará tres enfoques: texto extraído + embeddings densos, OCR + búsqueda, y modelo visual late-interaction.
Separá requisitos confirmados de supuestos. Indicá costos de infraestructura que debo medir, riesgos de privacidad y pruebas de calidad.
No inventes benchmarks propios ni prometas precisión sin evaluación.

Prompt: evaluar si de verdad mejora

Actuá como evaluador de retrieval.
Tengo consultas con páginas correctas conocidas.
Diseñá una tabla de evaluación con: consulta, página esperada, top 5 recuperadas, Recall@5, tipo de error, latencia, tamaño del índice y observaciones.
Agrupá los errores por páginas escaneadas, tablas, tipografía chica, imágenes y documentos versionados.
No inventes resultados. Dejá vacío todo lo que no se haya ejecutado.
Al final, sugerí una decisión: mantener, mejorar, o descartar este enfoque, con justificación.
06 / Decidir con criterio

No todos los PDFs necesitan visión.

Tu problemaEnfoque que probaríaTrade-off
Documentos de texto bien estructuradoExtracción de texto + embeddings densosMás simple y barato de operar.
PDFs escaneados con contenido textualOCR + índice textual, como base de comparaciónLa calidad depende del OCR y del layout.
Diagramas, imágenes, tablas y contenido mixtoEmbeddings multimodales late-interactionMás cómputo y complejidad para ranking.
Preguntas que necesitan una respuesta redactadaRetriever + modelo generativo + citasLa generación es otro componente, con errores y costos propios.
Un solo PDF cortoBúsqueda simple o lectura manualPuede que construir un pipeline completo no tenga sentido.

0.6B vs 9B

Yo empezaría con 0.6B, por menor demanda de recursos. Si falla en casos importantes y tengo capacidad de cómputo, compararía con 9B. Comparten espacio de embeddings, pero eso no elimina la necesidad de probar indexación y latencia.

Qué no confundiría

Embeddings ≠ OCR ≠ RAG ≠ chatbot. Los embeddings recuperan candidatos; OCR convierte imagen a texto; RAG usa recuperación para ayudar a generar; un asistente añade interfaz y políticas.

Errores que evitaría

  • Indexar un PDF entero sin guardar número de página y versión.
  • Pasar documentos privados sin autorización o compartir resultados entre usuarios sin control de permisos.
  • Suponer que un vector único y una base vectorial cualquiera sirven para MaxSim.
  • Comparar contra cero baselines; nunca sabrías si mejoró.
  • Omitir costos de GPU, almacenamiento y reindexación cuando cambian documentos.
  • Prometer respuestas correctas solo porque se recuperó una página relevante.

Checklist que usaría antes de implementarlo

  • Documentos autorizados, clasificados y versionados.
  • 10–20 consultas con páginas esperadas registradas.
  • Render de páginas consistente y auditable.
  • Dispositivo, versión y dependencias comprobados.
  • Soporte de índice multivector y MaxSim confirmado.
  • Resultados muestran fuente y página.
  • Permisos de lectura aplicados antes de entregar resultados.
  • Comparación con OCR/texto, latencia y costos medida.
Criterio GERO: no construiría “un chatbot para PDFs” de entrada. Haría primero un buen buscador que devuelva la página exacta. Si eso no funciona, agregar un LLM arriba solo consigue respuestas mejor redactadas sobre información incorrecta.
Primero retrieval, después producto

Antes de responder,
aprendé a encontrar.

Armá un experimento con tres PDFs y diez preguntas. Si recuperás bien, sumá interfaz, permisos y respuestas con citas. Si no, corregí la recuperación antes de agregar más IA.

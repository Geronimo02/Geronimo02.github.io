Gemini Skills

Cómo convertir prompts repetidos en procedimientos reutilizables y decidir cuándo una Skill alcanza — y cuándo necesitás una automatización real.

PRECIO / DISPONIBILIDAD: Google anunció rollout global en Gemini Chat para mayores de 18 años y disponibilidad en los niveles de suscripción Google AI. Workspace Business, Enterprise, Nonprofit y Education llega por fases. El anuncio inicial no confirma acceso para una cuenta gratuita estándar, así que no lo asumiría. No es una app independiente.

1. Qué cambió

Google está reemplazando Gems por Skills. Una Skill guarda instrucciones, se invoca con /, puede usar archivos de referencia y combinarse con otras Skills. Google también permite crear una Skill a partir de una conversación existente. Los datos de Gems personales migrarán automáticamente.

2. Cómo funciona

método repetido → instrucciones estables → Skill
caso concreto → variables / archivos → /skill → salida consistente

La diferencia importante no es “guardar un prompt”: es convertir una forma de trabajar en una pieza reutilizable.

3. Para quién sirve

Sí

Contenido, propuestas, prospección, análisis, research y cualquier tarea repetida con un método claro.

No

Procesos que necesitan webhooks, ejecución 24/7, acciones externas persistentes o lógica de backend.

5. Tres Skills que yo probaría primero

/prospecto

Entrada: empresa o URL. Salida: problema probable, evidencia, hipótesis de solución y primer mensaje.

/gero_post

Entrada: noticia o idea. Salida: hook, idea central, ejemplo práctico, criterio propio y CTA.

/propuesta

Entrada: necesidad del cliente. Salida: alcance, entregables, riesgos, supuestos y siguiente paso.

6. Cómo convertir un prompt en Skill

  1. Elegí un prompt que ya usás al menos varias veces por semana.
  2. Separá reglas estables de datos variables.
  3. Definí un formato de salida fijo.
  4. Agregá uno o dos ejemplos buenos.
  5. Probala con 10 inputs reales.
  6. Anotá errores repetidos y corregí las reglas.
  7. Recién después compartila o la combines con otras.

7. Prompt para diseñar la Skill

Convertí este método repetido en una Skill.
OBJETIVO: [resultado].
INPUTS VARIABLES: [lista].
REGLAS ESTABLES: [lista].
ARCHIVOS DE REFERENCIA: [si aplica].
OUTPUT OBLIGATORIO: [formato].
Si falta información crítica, pedila.
No inventes datos que no estén en el input o en las referencias.
Al final, verificá que la salida cumpla todas las reglas.

8. Errores que evitaría

  • Crear 30 Skills antes de comprobar que tres realmente ahorran tiempo.
  • Meter varios objetivos no relacionados en una sola Skill.
  • Confundir una Skill con un agente persistente.
  • Usar una Skill para acciones externas cuando debería existir una integración.
  • No versionar cambios importantes.

9. Comparativa

Skill: procedimiento reusable. Gem antiguo: experiencia personalizada más centrada en un asistente. Prompt suelto: flexible pero inconsistente. Agente/automatización: necesario cuando hay eventos, herramientas y ejecución persistente.

10. Qué haría yo

Empezaría con sólo tres Skills ligadas a trabajo que ya hago. Las probaría durante una semana y mediría tiempo ahorrado, correcciones y consistencia. Si una no resuelve algo repetido, la eliminaría.

11. Checklist

  • Nombre claro
  • Objetivo único
  • Inputs definidos
  • Formato de salida
  • Archivos de referencia
  • Ejemplos
  • Reglas de no-inferencia
  • Versión y fecha
  • 10 pruebas reales

Copilot dejó de ser solo chat.
Ahora Microsoft quiere que ejecute trabajo.

Guía práctica para entender Home, Code y Autopilot, qué cambia de verdad, cuándo lo probaría yo y dónde todavía no confiaría.

Mi lectura: lo importante no son tres nombres nuevos. Microsoft está cambiando la unidad de trabajo: de “pregunta → respuesta” a “pedido → ejecución → seguimiento → entrega”.

1. Qué cambió realmente

Home

Une Chat, Cowork y Office para que el contexto de trabajo viva en un solo lugar. La idea es retomar proyectos, delegar tareas y producir documentos sin saltar entre tantas superficies.

Code

Permite describir apps, dashboards y automatizaciones en lenguaje natural. Microsoft dice que usa tecnología de GitHub Copilot y apunta a resultados ejecutables, no solo a snippets.

Autopilot

Agente persistente con identidad, memoria, computadora y workspace. Está pensado para seguir pendientes, retomar trabajo días después y operar en segundo plano.

2. Disponibilidad y acceso

PRECIO / DISPONIBILIDAD: ACCESO LIMITADO / BETA. Home y Code empiezan rollout a través de Frontier; Autopilot amplía private preview. No lo trataría hoy como una función disponible para cualquier cuenta gratis estándar. Tampoco asumiría un precio independiente: forma parte del ecosistema Copilot/Microsoft 365 y el acceso depende del producto, plan, tenant y rollout.

3. El caso donde yo lo probaría primero

Lanzamiento de un producto

  1. Le doy objetivos, fecha, stakeholders y archivos.
  2. Home centraliza documentos y contexto.
  3. Code arma un dashboard de seguimiento o una automatización chica.
  4. Autopilot sigue pendientes y me trae excepciones.
  5. Yo reviso decisiones, aprobaciones y cualquier acción irreversible.

4. Cómo lo implementaría sin mandarme una macana

  1. Arrancaría con un workflow de bajo riesgo.
  2. Definiría qué puede leer, qué puede modificar y qué requiere aprobación.
  3. Separaría “preparar” de “ejecutar”.
  4. Usaría una carpeta o workspace acotado, no toda la empresa.
  5. Revisaría logs y resultados durante una semana.
  6. Recién después agregaría automatizaciones persistentes.

5. Mi checklist de seguridad

PreguntaQué haría
¿Puede borrar o enviar algo?Human-in-the-loop obligatorio.
¿Tiene acceso a información sensible?Principio de mínimo privilegio.
¿Puede ejecutar durante horas/días?Límite, logs, alertas y condición de parada.
¿Genera código?PR, tests, revisión y sandbox antes de producción.

6. Prompt que usaría para probar Home/Cowork

Objetivo: preparar el lanzamiento de [producto].
Contexto válido: solo los archivos de esta carpeta y los mails que te indique.
Entregables:
1. checklist con responsables,
2. borrador de documento ejecutivo,
3. tabla de riesgos,
4. pendientes que requieren decisión humana.
No envíes mensajes, no publiques y no modifiques archivos originales sin pedirme confirmación.
Al final, separá claramente:
- hecho,
- pendiente,
- bloqueado,
- requiere mi aprobación.

7. Prompt que usaría para Code

Construí un dashboard interno para [caso].
Antes de implementar:
- resumí requisitos,
- definí datos de entrada,
- listá integraciones,
- marcá supuestos.
Luego armá una primera versión mínima.
No agregues features no pedidas.
Incluí estados de error, logging y un checklist de deploy.

8. Cuándo NO lo usaría

  • Procesos irreversibles sin aprobación humana.
  • Acceso amplio a datos sensibles desde el día uno.
  • Automatizaciones donde no puedo auditar qué hizo.
  • Procesos mal definidos: automatizar caos sigue siendo caos.

9. Diferencia frente a ChatGPT/Claude/Gemini

No lo reduciría a “qué modelo es mejor”. La ventaja potencial de Microsoft es el contexto operativo dentro de Microsoft 365 y la persistencia del agente. Si tu empresa vive en Word, Excel, Outlook, Teams y SharePoint, esa integración puede pesar más que una diferencia chica de benchmark.

10. Qué mediría yo en una prueba

Tiempo ahorrado

Minutos humanos por tarea antes/después.

Errores

Cuántas correcciones humanas necesita.

Autonomía útil

Cuánto puede avanzar sin supervisionar cada paso.

Riesgo

Cuántas veces intenta acciones que deberían esperar aprobación.

GRATIS · OPEN SOURCE ELEGIBLE

Anthropic OSS Scanner: auditorías de seguridad con modelos fuertes, sin pagar

PRECIO / DISPONIBILIDAD: Anthropic lanzó OSS Scanner el 8 de octubre de 2026 como servicio gratuito y opt-in para proyectos open source elegibles. No es un scanner gratis para cualquier repositorio privado: está dirigido a mantenedores centrales de proyectos establecidos con impacto relevante y capacidad para triagear hallazgos.

Qué cambió

Los proyectos aceptados reciben escaneos periódicos con los modelos más capaces de Anthropic. Los reportes pueden incluir prueba de concepto de explotación, explicación, análisis de causa y una corrección sugerida cuando está disponible.

La diferencia importante

Este fast track envía hallazgos generados por modelos sin revisión humana previa. Eso acelera mucho la entrega, pero también implica falsos positivos o severidades mal clasificadas. El mantenedor conserva el trabajo crítico de validar y priorizar.

Para quién sirve

  • Mantenedores core de proyectos open source establecidos.
  • Librerías expuestas a inputs no confiables.
  • Proyectos con muchos usuarios o dependencias downstream.
  • Equipos que ya tienen capacidad para responder a findings high/critical.

Para quién NO

  • Repos privados de clientes o empresas que buscan un scanner comercial gratis.
  • Proyectos sin capacidad para triagear reportes frecuentes.
  • Equipos que necesitan findings human-verified antes de recibirlos.

Cómo anotarse

  1. Abrí un PR en anthropics/oss-scanner.
  2. Agregá projects/<proyecto>/project.yaml.
  3. Indicá el repo y contacto principal.
  4. Proveé un Dockerfile que deje el entorno listo y dependencias instaladas.
  5. Opcional: agregá threat_model.md con alcance y criterios.
  6. Corré tools/validate.py antes de abrir el PR.
  7. Anthropic valida manualmente que seas mantenedor core y revisa elegibilidad.

Config mínima

repo: https://github.com/tu-org/tu-proyecto
primary_contact: security@tu-proyecto.org
Dockerfile: Dockerfile

Threat model: lo que yo agregaría

# Alcance
- código que procesa input externo
- parsers, auth, serialización, uploads

# Fuera de alcance
- ejemplos
- benchmarks
- tooling de desarrollo no distribuido

# Prioridad
1. RCE / auth bypass
2. exposición de secretos
3. path traversal / SSRF
4. DoS explotable remotamente

# Formato esperado
- reproducción mínima
- impacto
- archivo + función
- parche mínimo sugerido
- test de regresión

Qué recibís

Después del alta, Anthropic realiza un primer escaneo y envía un paquete de reportes por email. Luego escanea periódicamente para encontrar vulnerabilidades nuevas o previamente omitidas. La frecuencia puede variar según capacidad del programa.

Seguridad y privacidad del scanner

Anthropic indica que los agentes de scanning corren en sandboxes endurecidos con acceso a Internet deshabilitado durante el análisis. El Dockerfile se construye con red para instalar dependencias y el audit posterior corre offline.

Limitaciones

  • Hallazgos del fast track no tienen revisión humana.
  • Puede haber falsos positivos o severidad incorrecta.
  • La elegibilidad se evalúa caso por caso.
  • No es equivalente a Claude Security, que es un producto comercial.
  • Necesitás preparar un entorno reproducible que el scanner pueda construir.

Comparativa

OSS Scanner: gratuito, para open source elegible, findings rápidos no revisados. Proceso CVD de Anthropic: disclosures con revisión humana. Claude Security: oferta comercial para integrar scanning en desarrollo empresarial.

Qué haría yo

Antes de anotarme, limpiaría el setup del repo y escribiría un threat model corto. Un scanner potente sin contexto te puede dar más ruido. Con alcance, severidad y formato definidos, aumentás la probabilidad de recibir algo accionable.

Checklist

  • Soy mantenedor core
  • Proyecto establecido
  • Capacidad de triage
  • Dockerfile reproducible
  • Tests pasan en container
  • project.yaml validado
  • Threat model recomendado
  • Contacto de seguridad activo

Próximos pasos

Si el proyecto encaja, revisá el template oficial, prepará el Dockerfile y abrí el PR. Si no encaja, no intentes forzar el programa: usá scanners OSS tradicionales y un workflow de revisión propio.

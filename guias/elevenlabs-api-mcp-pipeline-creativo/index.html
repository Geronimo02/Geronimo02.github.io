ElevenLabs ya no es solo voz.
Ahora podés montar una fábrica creativa.

Mi guía para bajar Image API, Video API, Templates API y MCP a un workflow de negocio real, con controles para no terminar generando basura a escala.

Mi lectura: la novedad importante no es que ElevenLabs haga “más cosas creativas”. Es que esas cosas ahora pueden vivir detrás de un API, un template y un evento de tu sistema.

1. Qué cambió

Image API

Generar y editar imágenes programáticamente usando modelos disponibles dentro de ElevenLabs.

Video API

Crear o animar video desde código, sin depender de repetir el flujo manual en la app.

Templates API

Diseñás un Flow aprobado una vez y después tu sistema cambia inputs sin reconstruir toda la lógica.

MCP

Los nodos pueden invocarse desde clientes compatibles como Claude, ChatGPT o Cursor, según integración y permisos.

2. Precio / disponibilidad

PRECIO / DISPONIBILIDAD: API DE PAGO / consumo. ElevenLabs indica que imagen y video usan el mismo pricing que su app para esos modelos; el importe depende del modelo y del output. No hay un único “precio de la API creativa”. Para producción, yo presupuestaría por asset terminado y no por llamada.

4. Por qué Templates me parece lo más potente

Sin templates, cada generación depende demasiado del prompt del momento. Con un template podés fijar estructura, referencias, estilo, voz, formato y orden de nodos. Después solo cambian variables como producto, claim, color o campaña.

5. Ejemplo real: ecommerce

Entrada

SKU, nombre, color, fotos base, beneficios y audiencia.

Salida

3 packshots, 2 variantes de anuncio, 1 video corto, voz y versión vertical para social.

Mi regla

No publicaría directo. Mandaría todo a una bandeja de aprobación y guardaría prompt/template/version/modelo usado.

6. Cómo lo implementaría en pequeño

  1. Elegí un solo producto.
  2. Hacé un template de 3–5 nodos.
  3. Definí un único formato de salida.
  4. Disparalo manualmente vía API o MCP.
  5. Guardá costos y tiempos.
  6. Recién después agregá webhook/evento automático.

9. MCP: cómo lo usaría yo

Para prototipar rápido: le pediría a Claude/ChatGPT/Cursor que ejecute el workflow usando un MCP ya autorizado. Para producción, preferiría que la lógica crítica viva en mi backend o automatizador, con credenciales y logs controlados.

10. Cuándo NO lo usaría

  • Si solo necesitás una pieza ocasional: la app manual puede ser más simple.
  • Si no tenés brand guidelines claras.
  • Si el costo de revisión humana es mayor que el ahorro.
  • Si el contenido requiere precisión legal o médica sin validación.

11. Checklist de producción

  • Template versionado.
  • Input schema validado.
  • Presupuesto por job.
  • Timeout y retries.
  • Salida guardada con metadata.
  • Revisión humana.
  • Webhook de estado.
  • Fallback si falla un nodo.

GPT-6.1 Sol + Computer Use

PRECIO / DISPONIBILIDAD: GPT-6.1 Sol está disponible en ChatGPT Work y Codex para Plus, Pro, Business, Enterprise y Edu; todavía no en Chat. En API usa gpt-6.1-sol. Precio estándar hasta 272K tokens de entrada: USD 2 por millón de input, USD 0,10 cached input, USD 2,50 cache write y USD 10 output. Free estándar no incluye Sol.

Qué cambió

OpenAI lanzó GPT-6.1 Sol el 29/09/2026. Mejora coding agentic, trabajo profesional, factualidad y computer use frente a GPT-6 Sol. En paralelo, Computer Use llegó al Agents API con navegador alojado por OpenAI.

Cómo funciona

Sol puede sostener un plan largo y usar herramientas. Cuando existe una API o integración estable, la usaría primero. Computer Use sirve como capa para interfaces web donde no hay una integración mejor.

pedido → plan → herramientas → navegador si hace falta → revisión → resultado + evidencia

Para quién sirve

  • Desarrollo y debugging de varios pasos.
  • Research y documentos complejos.
  • Operaciones con herramientas.
  • Workflows de navegador que hoy son manuales.

Para quién no

  • Clasificación o extracción simple a gran volumen.
  • Procesos donde una API estable ya resuelve el problema.
  • Tareas sin un criterio de éxito medible.

Mapa de decisión

  • Volumen barato: Luna o modelo menor.
  • Trabajo complejo cotidiano: GPT-6.1 Sol.
  • Máximo techo: Astra.
  • Interfaz sin API: Sol + Computer Use.

Caso práctico

Auditoría semanal de un ecommerce: leer métricas, abrir sólo paneles que no tengan integración, comparar con la semana anterior, preparar cambios y entregar una lista de pendientes con evidencia.

Implementación paso a paso

  1. Elegí una sola tarea repetible.
  2. Definí qué fuentes puede usar.
  3. Separá lectura de cambios externos.
  4. Definí límite de pasos, tiempo y presupuesto.
  5. Pedí revisión humana para acciones sensibles.
  6. Registrá resultados y errores.
  7. Probá 10 casos reales antes de ampliar el flujo.

Prompt base

Objetivo: [resultado].
Fuentes permitidas: [lista].
Primero resumí el plan.
Usá integraciones estables antes que interfaz cuando existan.
Antes de cualquier cambio externo, pedí revisión.
Si una herramienta falla, indicalo y no inventes el resultado.
Al final devolvé: hecho, pendiente, bloqueado y evidencia.

Precio y métrica

No mediría sólo tokens. La métrica que me importa es costo por tarea terminada: modelo, reintentos, herramientas y corrección humana.

Limitaciones

  • Las interfaces cambian y un flujo visual puede romperse.
  • Más autonomía implica más necesidad de observabilidad.
  • Sol puede ser innecesario para tareas simples.
  • Computer Use no elimina la necesidad de definir permisos y revisiones.

Comparativa

Astra conserva el máximo techo. Sol busca una relación capacidad/costo más práctica. Luna apunta a velocidad y volumen. Computer Use es una herramienta de interfaz, no un reemplazo universal de APIs.

Qué haría yo

Tomaría un workflow manual de 10–20 minutos, lo ejecutaría diez veces con Sol y mediría tasa de finalización, correcciones, latencia y costo. Sólo escalaría si el costo por resultado aceptado mejora.

Checklist

  • Objetivo medible
  • Fuentes permitidas
  • Límite de pasos
  • Presupuesto
  • Revisión humana
  • Logs
  • Fallback
  • 10 pruebas reales

Próximos pasos

Elegí un único workflow, definí baseline manual y compará durante una semana. No amplíes el alcance hasta tener resultados consistentes.
